# 中国厅 v2 可行性与底线核查（对抗式，只查客观项）

核查对象：`plan_v2.json`（19 厅 + 尾声）、`sources.json`；对照 `exhibit-kit/docs/STANDARDS.md`、`LESSONS.md`、`look.md`、`engine_plan.md`。
只查图源、时间与镜头、交接、性能、底线和展项的可玩性，好不好看不在这里评。

## 0. 计算基准

- 屏幕 1389×713 CSS px，dpr 2，也就是 2778×1426 设备像素。"不糊"的意思是：设备像素 ÷ 原图像素 ≤ 1（放大不超过 1:1）。
- 手卷"一臂宽"窗口按 look.md：约 1087×300 CSS px，画心 300 CSS px 高，合 600 设备像素。立轴整幅约 620 CSS px 高。
- 限速有两条：任务给的"平移 ≤ 屏宽 25%/s"（347 CSS px/s），`_rules` 自定的"手卷 ≤ 1/7 窗口/s"（约 198 CSS px/s）。
- 整屏看不到任何原作的时间，单次 ≤ 2 s（`_rules` ③）。
- 缩略图目验：`thumbs/` 下的 banpo、houmuwu、fengxian、ru、david_vases、moputao、bada、washeng、xubing、hanjiang；另外把本地 `trailer/src/s7_yuan_blue_white/david_vase_n01.jpg` 裁出瓶颈看了一下。

## 2. 跨厅问题（引擎和全局，先于逐厅解决）

**G1 停留不是静止画面，p=0/p=1 要重新约定（must）**
- 手卷和立轴停留会自动卧游（E3/E4），器物停留会转、会翻底（彩陶绕盆、汝窑翻底、青花转瓶）。engine_plan E3 已把交接改成 `ctx.from.image` = 离开那一刻的快照。
- 但有 4 处转场假定从停留的某个固定画面起步，快照交接下都会出错：青花（要从富春的任意位置走到卷末）、寒江（汝窑可能停在翻底的样子）、写意（大维德瓶可能转到了背面）、洛神（假定兰亭末两行在窗口里）。
- 改法二选一：
  - 这些转场的 ① 拍先做一个 ≤ 1.5 s、守限速的"回到本厅起始画面"；
  - 或者停留结束前 E9 强制回到起始画面，快照交接只用于观众手动拖过的情况。
- p=1 等于停留的**起始**画面。所以停留要从 p=1 那一帧开始走，不能另起一帧。相关厅：汴京（虹桥）、洛神（第一段）、富春（坡岸窗口）、帛画（见 §3-4）。

**G2 切片层级不够转场里的特写（must）**
- E3 只切两级（1200 高、2400 高）。转场特写要到接近 1:1 的原图：八大鸟眼、洛神回眸、清明虹桥、百骏马群、青花瓶颈、富春自题。
- 切片工具要为每个转场的**固定路径**出全分辨率块（或专用裁图），并在上一厅停留时预热解码。播放时不允许 `drawImage` 未解码的切片。

**G3 离线视频没有 alpha（must）**
- STANDARDS 规定预渲染用 H.264 mp4，而 H.264 不带透明通道。溪山"带 alpha 的云视频"要改成下面两种之一：
  - 整帧烘焙：卢舍那、云、范宽都烤进视频，首尾各留 ≥ 0.3 s 与 canvas 交叉，保证交接像素差 ≤ 1.0；
  - 亮度遮罩并排视频，用 WebGL 合成。
- VP9-alpha 只在 Chrome 可用，HEVC-alpha 只在 Safari 可用，要做两份，不推荐。

**G4 逐像素效果不能用 canvas 2D 实时做（must）**
- dpr 2 整屏约 400 万像素，逐帧 `getImageData` 或阈值运算都会超过 8 ms，而且 STANDARDS 禁止播放期间 `getImageData`。
- 必须 WebGL（换厅释放上下文）或离线 mp4 的：
  - 彩陶水面折射加水位；
  - 卢舍那受光顺序阈值；
  - 百骏按明暗分层显；
  - 汴京平面倾倒（透视变形，canvas 2D 只有仿射；分条近似在 dpr 2 下会出接缝，要用 WebGL 四边形或 CSS 3D）；
  - 溪山云（见 G3）。
- 可以 canvas 实时（预先准备好"另一版"整图，按移动的遮罩合成，用 `destination-in` 或混合模式）：
  - 洛神"湿润"：预渲染一张湿墨版，沿路径遮罩合成；
  - 汝窑窗光扫釉：预渲染一张受光版，渐变遮罩；
  - 寒江色场、蛙声压暗（`multiply`）、天书压印、青花圆柱（分条圆柱是明暗示意，可以）、写意和八大的镜头移动、尾声收卷。
- 所有"变暗、偏冷、去饱和"（吉金红陶沉下去、卢舍那冷蓝、蛙声日落）都预渲染成另一张图再交叉，**不用 ctx.filter**。

**G5 参观者作品上墙（should，违反 STANDARDS §2 "不让参观者的作品挂上墙"）**
- 彩陶"你画的盆放到墙上原件旁边"、汝窑"你的盆放在墙上原件旁边比"、青花"你烧的瓶和墙上大维德瓶并排"、秦俑"俑头排进坑里"（这一条还是拼贴，must）。
- 改法：对比只在展项面板里做（并排小图、墙色垫底），不进作品区。

**G6 输入规则（should）**
- 卢舍那展项"点按或空格"：空格归引擎，要去掉。
- 卢舍那"一手扶凿一手敲锤"、汴京"一手拉绳一手撑篙"都要两个同时输入，鼠标做不到。改成单指针的先后动作，例如拖动定角度后松手、再点按敲；或者拖动拉绳，按住撑篙，交替进行。

**G7 默认换厅手势占不占 15 s（note）**
- `look.room_change` 的"收卷—展卷"最长 1.5 s。它若在转场之前单独播放，14 s 的转场就变成 15.5 s。
- 应写明：这个手势叠在 ① 拍里（只动展签、缩略条），不另加时间。

**G8 "按笔顺落墨"用了不止一次（should）**
- 兰亭说"原迹像素，全馆只用这一次"。可是天书转场 ③ 又用"本馆楷体按笔顺写出"一整行，兰亭停留还有"按笔顺慢放一个'之'字"。
- 用字体按笔顺写，本身就碰了"不用仿书法字体"。天书这一行改成直接印出或淡入的正文字，不做笔顺。

**G9 整屏看不到原作超过 2 s（should）**
- 帛画 5–9 s 封土层占满屏约 4 s。
- 天书 4–8 s 只有白纸和一行引文，约 4 s。
- 九色鹿 2–11 s 是示意壁画（非原作），约 9 s。
- 各自的改法见逐厅。

**G10 展项机制重复（note）**
- 彩陶（转盘落彩）、青花（转盘画坯加入窑）、汝窑（拉风箱烧窑）：青花一个展项把前两个的机制都用了一遍。
- 不是底线，列出来给你决定。

## 3. 逐厅

### 3-1 彩陶（门厅 → 彩陶）风险：中高
- **图源**
  - 最佳源 `Banpo_motif.jpg` 4999×3412 目验是**内壁一组人面鱼纹的斜拍局部**，没有口沿，也不是整盆俯视。转场要"一圈暗水、边上露出一圈圈红陶内壁、盆心人面"，停留要"俯看盆心、绕盆沿慢转"，都要整盆正俯视图。
  - 备选 08736/08737（7641×5097）角度没看过。**这是开工的前提**。
- **图源**：即使有正俯视图，人面约占直径的 1/6（约 800 px）。吉金转场 ② 要"推近一组人面"铺满屏高，就是放大约 1.8×，会糊。推近要停在 ≤ 1:1。
- **文字**："盆心一张人面"不准确：人面鱼纹画在内壁（两组对称），不在盆心。墙文和画布字幕要改成"内壁"。
- **性能**：水面折射加环形水位要 WebGL 或离线 mp4（G4）。prep 写的"canvas 位移贴图均可"不成立。
- **交接**：p=0 是门厅那一卷"取出、解带"，可门厅是另一个页面，直接进 `/china/` 时前面还有 E8 的"印入场"。p=0 应定义为 `/china/` 载入后的入场画面，门厅点击动画的末帧要做成这一帧。
- **镜头**："顺着'监'字的大眼睛低头，转成俯视"是 3D 俯仰，2D 图做不出来。改成在暗场里交叉，或者纵向移出，不做透视俯仰。
- **展项**：转盘有惯性、按住落笔，可玩，难度 M。"你画的盆放到墙上原件旁边"见 G5。

### 3-2 吉金（彩陶 → 吉金）风险：高
- **图源（must）**
  - 那一刻要看清"中间人头、两边虎、虎口对着他"。最佳源 3380×4400 是展厅 3/4 角度，鼎耳约 300×400 px，而双虎纹在耳的外缘侧面，更小。
  - prep 的退路是"停在全形上，用火光点亮鼎耳"。这时人头在屏上只有十几 CSS px，看不出"同一个构图"，这个发现就不成立了。
  - 改法：图源审计先找鼎耳细部（国博、拓片耳部，全形拓 3930×5000 PD 的耳部先目验）；找不到，换第二名方案"泥范敲开，吉金是金色的"。
- **时间**：13 s。仰俯转中间全暗不到 1 s，合规。
- **性能**："红陶暖色沉下去"用预渲染暗版交叉；火光用低处渐变，轻微起伏，可以实时。
- **底线**：两图人头要对位，但中间隔着全暗，不交叉，不算橡皮变形。**合规**。
- **展项（should）**
  - 合范、倾倒（有黏度、会出气孔）、冷却、按位置和力度敲碎泥范、再加一根"年代"绳：流体、断裂、锈色，难度 XL，是全馆最重的展项。
  - "年代绳"其实是说明性滑杆，用户否定过这类东西。
  - 建议砍到两个有物理的动作：倾倒（黏度、速度决定缺陷）和敲范（落点决定碎法）。锈色改成展项结束时静静变化。

### 3-3 秦俑（吉金 → 秦俑）风险：高
- **图源（must）**
  - "认出陶工名字"要一张有释读的陶文戳印近照，**图源审计没收**。
  - ② 拍"探进鼎腹、火光斜照内壁、'后母戊'三字"要鼎腹铭文的**实拍**，也没收。拓片是黑白纸本，照不出"火光斜照内壁"的质感。
  - 两张都没有，那一刻就不成立。
- **镜头**：从鼎外"升过鼎口、探进鼎腹"是 3D 运镜，单张全形照做不到。要在暗场里切到铭文实拍。
- **时间（should）**：⑤ 后拉三拍"衣摆 → 脸 → 一号坑"只给 2.5 s，每拍约 0.8 s，太快。建议 4 s，总长 14.5 s，还在 ≤ 15 s 内。
- **底线**：
  - "这尊俑的脸"要求戳印和脸是同一尊俑，几乎找不到这样一对照片。改写成"一尊俑"，或者直接从戳印切到坑，免得不实。
  - 三张照片之间用短暗场，这个做法对。
- **展项（must）**：做好的俑头"排进坑里一列俑头之间"，是把参观者的作品合成进原作照片，既是拼贴又是参观者作品上墙。改成展项面板里一排模制头（同模不同脸），原作坑照不动。难度 M–L。

### 3-4 帛画（秦俑 → 帛画）风险：高
- **时间与镜头（must）**
  - ⑤ 11.5–14 s 要从最下段上行，经过墓主、双龙穿璧到日月，再退开看全幅。
  - 最下段按 ≤ 1:1 看（竖干约 880 px 宽，显示约 440 CSS px 宽），整幅约 2400 CSS px 高，上行约 1900 CSS px。2.5 s 里走完就是约 760 px/s，是限速的 2–4 倍。
  - 改法：转场只落到最下段（p=1 = 最下段）。"自下而上读到天门"交给停留（viewing 本来就这样写）。兰亭 p=0 取停留末帧"全幅"（配合 G1）。
- **图源（should）**：最下段竖干只有约 880 px 宽，铺满屏宽要放大约 3.2×。那一刻的画面最大只能到 1:1，约 440 CSS px 宽。
- **遮画（should）**：③ 5–9 s 穿过黄土、白膏泥、木炭三层，整屏约 4 s 看不到任何作品。竖向穿三层整屏，速度也超过 347 px/s。建议三层压成约 1.5–2 s；镜头不整屏跟着落，封土层只占画面下半，上方的俑脸还留在画里。
- **图源**：② "推到一张俑脸"：p=0 是一号坑全景，脸只有约 100 px。带彩痕的是**二号坑**跪射俑（另一张照片）。要在暗场里切过去，而且不能暗示它就是坑里那一尊。
- **性能**：漆皮卷翘离线，合规；剥落不做成粒子，合规。
- **展项**：举幡要按节奏甩，有物理手感，符合对标。T 形帛的布料模拟加贴图用 canvas 2D 按三角形 `drawImage` 很重，建议 WebGL 网格。难度 L。

### 3-5 兰亭（帛画 → 兰亭）风险：低
- **图源**：本幅 4513×1480。一行约 1300 px 高，显示 400 CSS px（800 设备像素），约 0.6，**够**。笔顺遮罩离线序列帧，合规。
- **事实**："仰观宇宙之大"按通行行款在神龙本第 8 行（"惠风和畅仰观宇宙之大俯察品"）内，不跨行。上墙前仍要按原图目验。

### 3-17 百骏（八大 → 百骏）风险：高
- **图源（must）**
  - 转场的全部依据是大都会 1991.134《百骏图》白描稿，sources.json **没有收**：像素、开放获取状态、和台北本逐段对位，都没核。
  - 要先补。对不上就退成"单匹马"（plan 已标），没图就换第二名方案。
- **底线（should）**
  - ④ "马身按原作明暗分 3–4 层依次显"：按亮度阈值分层显，会一块块冒出来，就是斑块溶解。
  - 改法：离线预渲染成"整体对比度逐步加深"（同一张原作从平涂的低对比版过渡到原图，全画面同时变化），不按区域阈值。
- **底线（should）**
  - ② ③ "石块下方的空白"：目验八大的石块下是地面和草，空白很小。在这里浮出一组马线：
    - 画面若还带着八大的石头，就是两件作品合成（拼贴、马线漂浮）；
    - 若推到只剩空纸，空白区域又小到要放大 > 2×。
  - 改法：选画幅左中部的大块空白（约 2000×1000 原图像素，放大约 1.4×），而且马线出现前八大的墨迹已经出画。"石下没有影子"改成在 ② 里先说。
- **性能**：离线或 WebGL（G4）。
- **展项（should）**：套马要一匹会跑、带影子的马。马的动画从哪来要定：不能从《百骏图》抠马做动画（抠图、漂浮剪影）。可以用 Muybridge 公有领域的连续照片描成动画序列。难度 L。

### 3-18 蛙声（百骏 → 蛙声）风险：低中
- **图源（should）**
  - 873×3461，整幅按约 620 CSS px 高挂时只有约 157 CSS px 宽，蝌蚪只有约 5 CSS px。那一刻"几只蝌蚪顺流而下，找不到一只青蛙"看不清。
  - 改法：落定后停留按 1:1（约 436 CSS px 宽）顺山泉往下走（viewing 已写"顺山泉往下"）。整幅只在落定那一拍出现。
- **时间**：13 s，全黑约 2 s，**合规**。整体压暗用 `multiply` 填色。
- **文字（note）**："一张几乎空白的高纸"不准确：上部两侧是大块浓墨山石（目验），画布字幕别这么写。
- **版权（note）**：大陆公有（1957 年卒，已过 50 年），美国状态待核。"中国现代文学馆，2013 年老舍家属捐赠"要核后再上展签。
- **展项（should）**：搅水带着蝌蚪群游。蝌蚪若从原作抠出来做成精灵四处游，就是"抠人"。要画成齐白石笔意的新蝌蚪（展项复制品上），或者只让水纹动、蝌蚪不动。难度 M。

### 3-19 天书（蛙声 → 天书）风险：高
- **图源（must）**：单字压印要真实天书单字。普林斯顿单页 484×843，一字约 50 px，按 100 CSS px 显示要放大约 4×。工作室图 ≤ 1354 px。在要到图（徐冰工作室、普林斯顿）之前，这个转场和展项"查字典"都做不了。
- **交接（must）**
  - ⑤ "镜头后拉：这是一页线装书，书页铺满地面，长卷从天顶垂下"：④ 压出来的是**平面的一页**，装置照片里的书页是透视拍的，位置、角度都对不上。
  - 连续后拉要么变形（橡皮），要么交叉重影（拼贴）。
  - 改法：
    - 那一刻就用一张真实的正面书页照片（压印发生在真书页上）；
    - 后拉在这张书页照片里完成；
    - 装置全景在停留里经暗场切换出现。
- **遮画（should）**：③ 约 4–8 s 只有白纸加一行引文，整屏约 4 s 看不到原作。压到约 2 s，或者让引文出现在蛙声画的底部留白里。
- **G8（should）**：引文"按笔顺写出"改成直接印出或淡入。
- **底线（should）**："山涧流出了画——下面是一片白宣纸"：画心下边和新加的白纸之间会有硬边（蛙声图带装裱边）。要做纸纹和色调连续的过渡，或者先到地头绫再进白纸。
- **展项**：拣字（吸附）、锁版、滚墨、刷、揭纸，每一步都有物理反馈，难度 L，受图源所限。

### 3-20 尾声（天书 → 尾声）风险：高
- **契约（must）**
  - ③ 5–9 s 里"交给尾声展项'盖观款'（观众盖完再继续；不盖则自动跳过）"：转场要等观众，`draw(p)` 就不再是 p 的纯函数，自动播放、暂停、seek、时长 ≤ 15 s 都失效。
  - 改法：转场只做"后拉到长案，停在拖尾" = p=1（尾声停留）。"盖观款"放在停留的展项面板里。收卷作为展项的收尾动画（面板内播放），或者做成尾声停留里的一个自动动作（`rest()` 可以按时间播放，但要满足 `init()` 和 `rest()` 能独立工作）。
- **物理（note）**
  - 从左往右收卷时，两卷之间露出的一段是**正面**。要做到"只经过卷背"，得先把已展开的天书段卷进去、两卷相接，之后只看得到两个卷筒的外表（背纸）。
  - 最后卷首段必须平铺朝上露出，才看得到"那一道黑彩"。建议按这个顺序写进 choreography，避免实现者在卷面上闪过作品。
- **时间（should）**：收卷时卷筒横穿约一屏，别超过 347 px/s，按 4 s 以上排。
- **展项**：印泥蘸取、按压时长决定印文虚实（鼠标没有压力值，用按住时长），可玩，难度 S。"可选字"要用真实篆刻印面的图，不用篆书字体（仿书法字体）。

## 7. 开工顺序建议（只按客观阻塞排）

1. **先补图源**（不补就做不了）：彩陶整盆俯视、吉金鼎耳细部、秦俑陶文与鼎腹铭文、百骏大都会白描稿、写意大维德瓶腹部龙带、天书单字与正面书页、卢舍那无游客晨光图。
2. **引擎契约**：G1（停留起讫帧与快照交接）、G2（全分辨率切片）、G3（无 alpha 视频）、G4（WebGL 清单）。
3. **样板厅 八大**：按 3-16 的数值改下落比例和展项，就能进入制作。它不依赖任何缺失的图源。备选汝窑要先解决 3-11 的"盆藏在哪"和开片核实。
