# 踩坑与对策

按"机器与流程 → 素材 → 画面 → 声音 → 交付与保存"排。每条：出了什么事 → 怎么办。

## 一、机器与流程

### 1. 8 GB 内存：重活必须排队拿锁
- **事**：先导片 v3 制作 7 路同时渲染，内存严重换页，助手一条命令 3 分钟没输出被判卡死，12 个任务被拉起 50 次，6.2 小时后失败。另一个项目多个 headless 渲染同时开，Claude 桌面版被挤爆强退。实测：交换区用到 6.6 GB；配音试声时可用内存只剩 71 MB；整片编码时空闲 0.15 GB。
- **对策**：
  - 任何会占 >1 GB 内存或跑满 CPU 的命令（加载整幅高清图、torch、渲染、长片编码、whisper）一律 `lockf -k $CHINA_ART_ROOT/series/.heavy.lock <命令>` 串行。短测试（≤10 s、低分辨率）可以不拿锁，但要轻。
  - 同时在跑的助手 ≤3 路一批（每个 claude 进程本身约 300 MB）；渲染进程同一时间 1 个。
  - 大图一律 `np.memmap` / `np.load(mmap_mode='r')` 分块读，Python 峰值控制在 2.5 GB 内。
  - 1080 排队脚本要"每段单独拿一次锁"，别一次拿锁跑完全部，好让别的短任务插空。
- **开第二条渲染通道**（用户说"内存有空余就多开几个"时）：把 `.heavy.lock` 改名（已在排队的继续走旧 inode = 通道 1），新建同名空文件（之后新调 lockf 的走新 inode = 通道 2）。同时挂内存告警（Monitor：可用内存低于 300 MB 持续 30 秒就报警）。实测两路可以，三路以上换页变慢。

### 2. 长命令：nohup 后台 + 短轮询
- **事**：工作流里的助手一条命令超过约 3 分钟没有输出，会被判卡死重启，前面的活白做。
- **对策**：超过 1 分钟的命令一律 `nohup lockf -k <锁> <命令> > log 2>&1 &`，再用 ≤60 秒的短命令看日志（`tail -3 log`）。不要前台长 sleep。整片渲染约 7–8 分钟、pan_speed_check 1–3 分钟、手机版两遍编码约 4 分钟，都要后台。

### 3. 改需求时怎么停流程、怎么续跑
- **用户中途改主意**（"先暂停保存""1080先别做了""先别改了，先用原来的拼好再说""不用延长很多"）：
  1. 立刻 TaskStop 停掉在跑的工作流/后台任务；只停受影响的那部分，不相干的渲染可以让它跑完。
  2. 改分镜/改版单（只留最终版本），再改工作流脚本里对应的数字或提示词。
  3. 续跑：`Workflow({scriptPath, resumeFromRunId})`——脚本里最长的未改动前缀走缓存，第一个改动的 agent() 起重跑。**把会变的 agent 放在后面**，前面已完成的素材/配乐/旁白就不会重做。
  4. 如果续跑会让某个已经做了一半的助手从头重来（例如北宋千里江山渲到一半被停），就别 resume 整个 run：按 HANDOFF 手动重渲那一段，再单开一个只做总装的小工作流。
- **助手还在跑、只改一个参数**：用 SendMessage 直接转告那个助手（"用户刚放宽了版权标准"），不用重开。
- **总装助手还在跑、方案变了**：在它的目录写一份覆盖说明（南宋的 `assemble/NOTE_FOR_ASSEMBLY.md`："先用雾，别等转场片"），提示词里早就写了"开工前读这个文件"。以后的总装提示词里都预留这一句。
- 用户说"先暂停保存"：停进程，写 `HANDOFF.md`（已完成什么、在跑到哪、怎么重跑、下一步），在记忆里写"恢复入口"。下次一句"继续"就能接上。
- 会话重启时后台 run 全停：靠记忆 + HANDOFF 接上，用 `resumeFromRunId` 续跑。

### 4. 防休眠
- 长流程（每集 3–4 小时）开跑前打开 keep-awake，理由写清（"用户休息期间后台渲染还要跑几个小时"）。

## 二、素材

### 5. 台北故宫 IIIF：Python 证书报错，用 curl
- **事**：`urllib` 访问 `digitalarchive.npm.gov.tw` 报 SSL 证书错误。
- **对策**：清单和图都用 `curl` 取。清单 `https://digitalarchive.npm.gov.tw/Integrate/GetJson?cid=<id>&dept=<P|U>`；全图 `https://iiifod.npm.gov.tw/iiif/2/<部门码>%2F<label>/full/full/0/default.jpg`。**单张上限约 7 MP**，要更高分辨率就把多张局部拼起来（万壑松风 8 张局部拼成 4876×6332：共享径向畸变 + 每块单应 + 平滑位移网格，SIFT + 相位相关解，拼完跑重叠区错位检查，中位 0.10 px）。

### 6. 清明上河图：名画记那张是明代仿本
- **事**：Commons 上 `File:清明上河图卷.png`（21844×1109，名画记来源）原本被指定为校色参照，查页面才发现是《明人清明上河图卷》——大片青绿山、构图也不同，不是张择端本。
- **对策**：已改名 `NOT_ZHANG_ming_copy_minghuaji_21844x1109.png` 留存、不用。校色改用故宫博物院官网藏品页的虹桥段官方图（模板匹配定位 → 3×3 矩阵 + 偏移最小二乘，全局一个变换）。**凡是"参照图"，也要先核它是哪一本**；同名作品有摹本、仿本、传本时，展签和旁白都写清楚。

### 7. 超大图
- 千里江山 PNG 153767×6110、约 2 GB，只能流式读：先转 ds3 缩略 raw，再按列块取全分辨率。PNG 大图一律用流式解码工具（南宋用的 C 写的 `pngstream`，内存 <5 MB）转成无头 raw，**别整张读 PNG**。
- 夜宴 TIFF 588 MB（LZW + predictor 2）：逐条包成小 TIFF 交给 libtiff 解（峰值约 1.2 GB），只留要用的一段 raw。
- 读大图统一：`np.memmap(path, np.uint8, 'r', shape=(H, W, 3))`，文件名写上 `_<W>x<H>.rgb`。

### 8. 图源的许可与出处
- Commons 下载要带通用浏览器 User-Agent，请求间隔 ≥6 s。
- 寒江独钓：Commons 标公有领域，但原出处网站写着禁止转载；东博 ColBase 版许可干净但只有约 3000 px。用哪个、怎么署名在 INDEX 里写清楚。
- 南宋官窑：先核实大都会馆方信息（Met API：Southern Song, Guan ware）再用；"是不是某窑"这类判断以馆方为准，不以缩略图为准。
- 坐标要在带网格的核对图上看过再写进 INDEX（误差 ±20–30 px），推到 1:1 前再实看一次。

## 三、画面

### 9. 转场设计失败案例："斧劈接斧劈"
- **事**：南宋 s1→s2 想从李唐崖壁的斧劈皴"一刀劈开"，露出踏歌巨石同样的斧劈皴。单派一个助手渲了 75 分钟，结果：在全景尺度上斜切成条 = **拼贴**；而且按推拉 ≤6%/s 的限速，9 秒内根本推不到能看清皴法的特写。自评失败弃用。又试"收画、挂画"（立轴卷起→墙光换色→踏歌展开），用户叫停："先别改了，先用原来的拼好再说"。看完整片才发现真正的问题是雾太多，最后用一个 1.5 秒的干净叠化解决。
- **对策**：
  - 转场先做**可达性计算**：起止景别差几倍、限速下要几秒、窗口够不够；不够就换想法，不硬做。
  - "两件作品同一种笔法"是好联系，但必须在**能看清笔法的尺度**上发生；全景尺度的切分、拼接必然是拼贴。
  - 先把整片按原方案拼出来给用户看，再议单个转场；别让一个转场卡住整集。

### 10. 雾：会变成空白屏，也会遮画
- 北宋 v1 的雾是一片均匀米黄 → 要多层体积、边缘翻卷、浓淡起伏，峰顶先从雾里露出；加了客观检查"雾中任一帧不许大面积平涂"（24×24 块去绢纹后 std<1.2 的比例 ≤25%，浓淡离散度 ≥5）。
- 南宋 v1 雾用太多、遮画 → 全片去雾。雾一集最多一次。

### 11. "动效不明显"
- v1 的动效在电脑上看得出、手机上看不出。以后按"手机上 1 秒内看出在动"定量级（`STANDARDS.md` §3），每段先出 ≤10 s 预览在手机尺寸看。

### 12. 速度检查的误报
- `pan_speed_check.py` 用相位相关测全局位移，无纹理的渐变（融釉、满屏石青化开）会出孤立单帧误报；转场、硬切也会让个别帧虚高。报警段要人眼复核，不要为误报改画面。

### 13. 段与段接不上
- 每段的起止状态必须严格照分镜的段窗口表（两端留重叠给转场用），帧 0 = 窗口起点；转场需要的遮罩（水面、涟漪、水纹线、开片）由段导出同时段的遮罩 mp4。各段把实际节拍写 `beats.json`（全局秒），总装以它为准。

## 四、声音

### 14. 配乐版权
- **事**：南宋制作时选了吴兆基《平沙落雁》（雨果唱片 1987 年录音），时长和气质都最合适，但录音在版权期内（到约 2037 年），本机那份是 Internet Archive 个人上传的未授权拷贝。发布前才换成 Caro《梅花三弄》，踏歌顿足原本对着那首曲子的起音，换曲后没再对。
- **对策**：选曲时就把"要公开发布"当前提，许可不干净的录音不进首选；踩拍类高光最后再对最终配乐的起音表。许可状态照实写进 `music_DECISION.md`。

### 15. 读音（edge-tts 云健）
- 合成后用 whisper 听写回来（faster-whisper base 初听，mlx 版 large-v3-turbo 复核；base 对中文太吵），转拼音逐字比；多音字另做"同音替身"比对（MFCC-DTW + F0 轮廓）。
- 读错的只在送去合成的文本里等长替换（`PRON`），字幕原文不动。两集实际修过的：
  - 「谿山行」→「溪山形」（谿读成 qī，行读成 háng）
  - 手卷之「卷」→「绢」（读成 juǎn，两集都有）
  - 「支钉」→「支丁」
  - 「一一二四年」→「壹壹贰肆年」（两个"一"粘连；试过阿拉伯数字、全角数字、加符号都不行，加顿号又停太久）
  - 「朝阳」的朝→「招」（读成 cháo）
  - 句首「笔越少」的笔→「比」（被合成成上扬调，听成"别"）
- whisper 把专名听成常用词的不算错（例如把人名听成同音常用词），以拼音比对为准。
- 下一集要重点核的：多音字（朝、行、卷、传、横、调、藏、重……）、年份数字、专名。

### 16. 试声别让用户等
- **事**：配音选声时装了 4 个本地开源模型，合成全卡在同一把渲染锁后面，40 分钟没东西给用户听，用户连催。最后用户"我就听一下声音就行"。Spark-TTS 在 M2 上出 nan，CosyVoice2 缺 pyarrow。
- **对策**：试声先发现成的原声/样本，合成排在后面；不替用户默认音色。音色已定云健，后面各集直接用。

## 五、交付与保存

### 17. 硬链接备份会被一起改掉
- **事**：北宋改版前用 `ln` 做了第一版备份，重渲时 `ffmpeg -y` 原地截断写入，备份跟着变，第一版三段丢了。
- **对策**：备份一律 `cp`（大文件也 cp）；覆盖成品前脚本自己先 `cp x.mp4 x.mp4.bak_<时间>`。

### 18. 废纸篓被清空，旧版全丢
- **事**：清理时把被替代的成片、中间版本移进废纸篓（没 rm），之后废纸篓被清空，先导片成片、北宋各中间版、本地 TTS 环境 17 GB 永久删除；做幕后片时只剩联系表和抽帧。
- **对策**：
  - 清理前先 `lsof +D <目录>`、`ps` 查有没有别的会话在用（曾误删另一会话正在录视频用的目录）。
  - 以后可能要回看的（每版联系表、高光预览、改版前后对比帧）清理前先压成小文件留在工程里；移废纸篓前告诉用户"清空废纸篓后这些就没了"。
  - 不替用户清空废纸篓。

### 19. 手机预览的大小限制
- 发给用户手机看的文件上限约 30 MB：4:52 的 720p 成片约 70 MB，另压 854×480 两遍编码（视频约 640 kbps + AAC 96k）约 26 MB。用户说不要手机版就别压。

### 20. 不要改上一集的文件
- 做新一集时，上一集的段、总装、配音文件一律只读；要复用就复制到新一集目录再改。公共引擎只许新增文件，不改现有行为（改了会让上一集不能重渲）。

## Python 解释器被新装的 Homebrew python3 顶掉（2026-09-30）
- 现象：`python3 assemble.py …` 报 `No module named 'cv2'`。原因：后来装的 `/opt/homebrew/bin/python3` 排在 PATH 前面，里面没有 OpenCV；两集代码一直是用系统的 `/usr/bin/python3`（3.9，带 cv2 5.0）跑的。
- 对策（已处理）：已给 Homebrew python3 用 `python3 -m pip install --user --break-system-packages opencv-python pillow numexpr scipy scikit-image pypinyin` 装齐渲染依赖（装在 ~/Library/Python/3.14，不动 Homebrew 自身），两集总装抽帧实测可跑；`/usr/bin/python3` 也照样能用。深度估计要的 torch/transformers 没装进 Homebrew python，需要时用 `/usr/bin/python3` 或 bootstrap 建的 venv。新环境用 `scripts/bootstrap.sh`。
